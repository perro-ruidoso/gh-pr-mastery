Where Linear sits

This course's position is fixed in MISSION.md: GitHub Issues is the source of truth; Linear is the project-management layer above it. That is why M05 had you tell the engineering skills that issues live on GitHub, and why every ticket this week was filed with gh. Linear's job, from today, is to show that work — as a team's board, with statuses that move — and to do so from the GitHub activity itself, not from anyone clicking.

Linear's model is not GitHub's, and Week 6 (M33) takes the differences seriously. For now, one term: a Linear team owns issues and gives them their identifier prefix. You will create one team for your Instance; its key (say FLASH) becomes the FLASH-12 in every synced issue's title.

Two capabilities, one integration

Linear's GitHub integration does two separable things, and the objective needs both:

CapabilityWhat it doesAssessed in
PR and commit linkingA branch name or PR title that contains a Linear issue ID, or a magic word in a PR description, moves the Linear issue's status: "by default, we will move linked issues to 'In Progress' when PRs are open and 'Done' when PRs merge."M12 (preview), M34 (fully)
GitHub Issues SyncCopies issues between a GitHub repository and a Linear team — "title, description, status, assignee, labels, sub-issues, comments" — one-way or two-way.M12

Enabling the integration

  1. Create a workspace and one team. Free plan. Name the team after your Instance; its key is the prefix every synced issue will carry.
  2. Install the GitHub integration. "Go to Setting > Features > Integrations > GitHub" and authorise. Linear's permission note matters for you specifically: "To grant Linear organization-level access in GitHub, the integration must be installed by a GitHub organization owner. If you only need repository-level access, a repository administrator can install the integration instead." You are not an org owner of perro-ruidoso; you are, as its creator, an administrator of your Instance. Check before you start — gh api repos/perro-ruidoso/flashcards-<handle> --jq .permissions.admin should print true. If the instructor has already installed the app at org level (instructor guide, Part 5), you will only be choosing your repository.
  3. Link your repository to your team for Issues Sync. "From the GitHub Issues section of the GitHub integration settings, click the + icon, then select the GitHub repo and Linear team to link." Choose two-way: "issues created in either the GitHub repo or Linear team will create a synced copy in the other software." Note the constraint: "only one repo can be configured for two-way sync at a time" — fine, you have one.
Forward only

"This will only sync issues going forward." And again: "GitHub Issues Sync will only sync newly created issues." The spec and tickets you filed in M09–M11 will not appear in Linear when you connect. That is not a fault; it is the reason the verification on page 2 creates a new issue and watches it cross. If you want the existing backlog in Linear too, Linear's documentation points to its GitHub Issues Importer for "historical GitHub Issues" — optional for A2, and worth doing only after the sync is proven.

Why not make Linear the tracker?

Because the engineering skills would lose their first-class support (M05), because a fresh agent session reads gh issue view and not a Linear board, and because a source of truth that two systems both claim to be is the situation Week 6's M35 exists to reason about — duplication, sync lag, and permissions. You are building the evidence for that argument now: after this week, every status change in Linear should be traceable to a GitHub event. If one is not, you touched it by hand, and that is exactly what the objective says not to do.

Linear's role in this course, in one line?
The project-management layer above GitHub. GitHub Issues is the source of truth (MISSION.md).
The two capabilities of Linear's GitHub integration?
PR/commit linking (branch names, PR titles, magic words move status) and GitHub Issues Sync (copies issues between a repo and a team).
What does Issues Sync copy?
"title, description, status, assignee, labels, sub-issues, comments" — one-way or two-way.
Free plan: what is gated, and what is actually limited?
Issue sync is a Core feature on every plan. Free limits: 2 teams, 250 issues, 10 MB uploads.
The two plan-gated items on the integration page?
GitHub Enterprise Cloud support (Enterprise plan) and AI-written titles from magic words (Business and Enterprise).
Does connecting Linear import your existing issues?
No — "only sync issues going forward." Historical issues need the GitHub Issues Importer.
Who can install the integration, per Linear?
Org-level access: a GitHub organization owner. Repository-level: a repository administrator — you, on your Instance.
How many repos can be in two-way sync at once?
One. Several repos can feed one team one-way.
