Issue Templates

A template shapes what a human is prompted to write. An agent never sees it. Knowing which of your collaborators is which decides where the four-section shape has to live.

M08 · Issues Bloom: Apply Assessed by: A2 (checker)

Objective: Apply labels, issue types, and issue templates so a backlog is filterable and ready work is findable.

M08 pages 1Labels and Issue Types 2Issue Templates

What a template is

GitHub offers two kinds. A Markdown template is a .md file with YAML front matter whose body becomes the starting text of a new issue. An issue form is a .yml file describing "customizable web form fields" — dropdowns, required text areas — and is "currently in public preview and subject to change." Both live in one place: the .github/ISSUE_TEMPLATE folder, and both take effect only "once these changes are merged into the default branch."

Two small rules that bite: the template's name "must be more than 3 characters" or "the template won't be shown when creating an issue," and if you have several, "prefix the filenames with a number" (1-bug.yml, 2-feature-request.yml) to control their order in the chooser.

The course's one template

Your Instance needs exactly one: the ticket shape from M07. This file was committed to a throwaway Instance's main and used for the transcripts below.

.github/ISSUE_TEMPLATE/ticket.md 
---
name: Ticket
about: One unit of agent-executable work. Fill every section; an agent will read it cold.
title: ""
labels: needs-triage
type: Task
---

## Context

Why this exists, in two sentences. What is true today, and what will be true after.

## Acceptance criteria

- [ ] Observable, checkable statements
- [ ] Including the test that must exist

## Out of scope

Explicitly, what this ticket does not do.

## Blocked by

Nothing, or the issues that must land first and why.

GitHub documents the metadata keys in one sentence: "You can also add these details in the issue template with title, labels, type, or assignees in a YAML frontmatter format." Three of them carry metadata from page 1: labels: needs-triage puts every human-filed issue into the triage state by default (it is not ready for anything until someone says so), and type: Task sets the issue type. The body is prompts, not content — the placeholder under Acceptance criteria describes what a criterion is without pre-filling any. That restraint is deliberate: seed/SPEC.md §8 says a template "must not pre-fill the acceptance criteria M07 asks students to write," because a pre-filled template becomes a form people submit without thinking.

Who a template is for

This is the part that surprises people. Try to use the template from a script:

$ gh issue create --template Ticket --title "Due-date filtering"
must provide `--title` and `--body` when not running interactively

$ gh issue create --template Ticket --title "Due-date filtering" --body-file -
`--template` is not supported when using `--body` or `--body-file`

Both captured as shown. --template is "starting body text" for an interactive session — it pre-fills the editor a human is about to type into, and it is refused when a body is supplied from a file or a pipe. So a template is reached in exactly two ways: the web UI's issue chooser (which gh issue create --web opens), and an interactive gh issue create at a terminal. An agent uses neither. Claude Code files issues with gh issue create --title … --body-file …, exactly as docs/agents/issue-tracker.md told it to in M05, and it gets the four-section shape from what it has already read: CLAUDE.md, and the /to-tickets skill's own issue template.

Humans

Get the shape from the issue template: the web chooser or interactive gh issue create.

Get the labels and type from the template's front matter.

Agents

Get the shape from CLAUDE.md and the skill's own template; never see .github/ISSUE_TEMPLATE.

Get the labels and type from flags: --label, --type, --parent, --blocked-by.

The consequence for you: the four sections have to be stated in both places, and kept the same. A repository whose template says one thing and whose CLAUDE.md says another will produce two shapes of issue depending on who filed it — and a filter that assumes one shape will silently miss half the backlog.

Verifying it landed

Templates are files, so the check is a file check on the default branch — the same contents endpoint check_a1.py used for docs/agents/:

$ gh api repos/perro-ruidoso/flashcards-<your-handle>/contents/.github/ISSUE_TEMPLATE --jq '.[].name'
ticket.md

What the API cannot tell you is whether the chooser shows it. Open gh issue create --web once, confirm "Ticket" appears with its about line, and cancel. If it is missing, the usual cause is a name of three characters or fewer, or the file sitting on a branch that is not the default.

The optional config.yml

A second file in the same folder controls the chooser itself. Setting blank_issues_enabled: false means "Contributors with Read or Triage roles will only see the configured templates" — useful on the shared upstream repository in Week 6, where outside contributors file issues, and unnecessary on your Instance, where the only human is you.

Hands-on checklist

check_a2.py verifies a Markdown template exists under .github/ISSUE_TEMPLATE/ on the default branch, its front matter names a type, and its body contains the four headings without a pre-filled criterion.

Self-check

1. Claude Code files a ticket in your Instance with gh issue create --title … --body-file …. Which of these shaped the body?

B. A template pre-fills an interactive editor and is refused alongside --body-file ("not supported when using --body or --body-file"). Nothing is applied automatically to API-created issues (A, D), and config.yml only configures the chooser (C).

2. You add a template on a feature branch and open the repository's issue chooser. What do you see?

D. GitHub: "Once these changes are merged into the default branch, the template will be available for contributors." Until then it is just a file on a branch.

3. Why does the course template leave the Acceptance criteria section as a description rather than a filled-in example?

A. seed/SPEC.md §8 makes it a rule: templates "must not pre-fill the acceptance criteria M07 asks students to write." The other options describe restrictions that do not exist.

Ask your teacher

Ask Claude Code: "Read .github/ISSUE_TEMPLATE/ticket.md and CLAUDE.md. If a human and you each filed a ticket for the same work, would the two bodies have the same headings? If not, what should change, and in which file?" The right answer changes CLAUDE.md, not the template. Bring anything still unclear to the weekly meeting.
