GitHub Pull Requests for Agentic Coders

Six weeks on running real development work through pull requests while Claude Code does the typing. The subject is the workflow — issues, dependencies, branches, diffs, review, gates — not the app you build with it.

Your bottleneck is no longer writing code. It is specifying work small enough to hand over, and reviewing what comes back. Pull requests are where both of those happen. Over six weeks you will decompose a spec into tickets with honest dependency edges, hand one ticket at a time to a fresh agent session, own the diff that comes back, and configure the gates that stop bad work from landing — then sit on the other side of the table and maintain a repo other people contribute to.

How these pages work

Each week has a hub listing that week's mastery objectives. Every objective has an entry page and, where it is dense, a few short supporting pages — each self-contained, each ending with a self-check matched to the objective's Bloom level, a flashcard deck for retrieval practice, and a where-to-learn-more list, plus a hands-on checklist where the objective is something you do. Assignments are graded from your repository's actual state, so the work itself is the evidence.

Before you enrol: your coursework is public

Every repository in this course is a public repository. This is a requirement, not a preference — merge queue, which Week 5 depends on, is available in any public repository owned by an organization but requires GitHub Enterprise Cloud for private ones. Public repositories also run Actions for free, so the CI you configure costs nothing to re-run. Nothing personal goes in these repos; the practice application is a flashcard CLI chosen for exactly that reason.

Weeks

  • Week 1M01–M06
    The Machine You Work In

    What a pull request actually is, the merge base and why your diff looks the way it does, reading work from the terminal, configuring your repo for the engineering skills, and reading this course's own repository as evidence.

  • Week 2M07–M12
    Issues as Units of Agent Work

    Issue bodies an agent can execute, labels and issue types, /to-spec, tracer-bullet decomposition with /to-tickets, decomposition into sub-issues, blocking edges recorded as issue dependencies, Mermaid graphs, and wiring Linear to your repo.

  • Week 3M13–M18
    Branches and the Shape of a Diff

    Branch-per-issue with gh issue develop, what makes a diff reviewable, the PR body as a contract and the keyword that closes the issue, stacked PRs and the retarget that makes the keyword work, resolving the conflict that follows with /resolving-merge-conflicts, and the rest of the skill toolbelt.

  • Week 4M19–M24
    Owning the Diff

    Comments versus reviews versus suggestions, resolving and re-requesting and what reviewDecision really records, /code-review and giving each finding a verdict, writing comments a peer can act on, answering review as the author through Claude Code, and filing what review uncovers with /qa instead of fixing it in the open PR.

  • Week 5M25–M30
    Gates and Automation

    CI with Actions, rulesets and required checks, CODEOWNERS and teams, merge versus squash versus rebase, merge queues, and reading a working Claude GitHub Action workflow.

  • Week 6M31–M36
    The Maintainer Seat

    Contributing from a fork, triaging other people's PRs, Linear's model against GitHub's, driving status from git activity, deciding where truth lives, and your Personal PR Workflow Playbook.
