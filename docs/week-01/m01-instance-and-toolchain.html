The three repositories, and which one is yours

This course uses three repositories, and confusing them is the single most common Week 1 mistake.

Course repo gh-pr-mastery

These pages. You read it; you never push to it. You will analyse its pull requests in M06.

Template flashcards-seed

A Python flashcard CLI with tests, CI, and a prepared backlog. You never push here either — you make a copy of it.

Yours flashcards-<handle>

Your Instance: your own copy of the template, created today, worked in for six weeks.

A fourth, flashcards-upstream, appears in Week 5. Ignore it for now.

Step 1 — Accept the organization invitation

You will have an email invitation to the course organization. Accept it, then make your membership public:

  1. Go to the organization's People tab.
  2. Find yourself, and change your membership visibility from Private to Public.
Why this one matters later

GitHub hides organization membership by default. When your membership is private, other tools — including the Claude GitHub App we use in Week 5 — cannot see that the organization grants you write access, and will refuse to act on your comments. Anthropic's documentation calls this out explicitly. Two minutes now saves a confusing hour in Week 5.

Step 2 — Authenticate gh with the right scopes

Install the GitHub CLI if you have not, then:

$ gh auth login
$ gh auth status

The status output tells you the account and — the part people skip — the token scopes:

github.com
  ✓ Logged in to github.com account your-handle (keyring)
  - Active account: true
  - Git operations protocol: https
  - Token: gho_************************************
  - Token scopes: 'gist', 'read:org', 'repo', 'workflow'

Those four scopes are enough for everything through Week 4. A scope is a permission attached to your token; if a command needs one you do not have, gh fails with a message naming it. You can add scopes at any time without logging in again:

$ gh auth refresh -s read:project
Check your own

Run gh auth status now and read the scopes line. If repo and read:org are missing, nothing else in this course will work. A1's checker reads this, so fix it today rather than on the due date.

Step 3 — Create your Instance from the template

flashcards-seed is a template repository, not an ordinary one. Creating from a template is not the same as forking, and the difference is worth understanding now because you will do both in this course — template today, fork in Week 6.

From a template

Per GitHub's docs, a repository created from a template "starts with a single commit" — none of the template's history comes with it.

Your commits do appear in your contributions graph.

No ongoing relationship to the original. It is your repository.

From a fork

A fork "includes the entire commit history of the parent repository."

Commits to a fork do not appear in your contributions graph.

Stays linked to the parent — which is what makes cross-repo pull requests possible (Week 6).

Template is right here: you want a clean history that is yours, because from Week 3 onward your history is the thing being read and graded. Create it from the terminal:

$ gh repo create perro-ruidoso/flashcards-<your-handle> \
    --template perro-ruidoso/flashcards-seed \
    --public \
    --clone

--clone drops a local copy in the current directory, so you can go straight in:

$ cd flashcards-<your-handle>
$ git log --oneline
a1b2c3d (HEAD -> main, origin/main) Initial commit

One commit. That is the template behaviour, confirmed from your own terminal rather than taken on faith.

Yes, --public is required

Not a typo and not laziness. Merge queue — which Week 5 depends on — is available in any public repository owned by an organization, but for a private repository it requires GitHub Enterprise Cloud. A private Instance would put that objective out of reach. Public repositories also get unlimited free Actions minutes, so the CI you configure in Week 5 costs nothing to run over and over. Keep nothing personal in this repo.

Step 4 — Confirm the app runs

The Instance is a small Python CLI. Set it up and run its tests once, so that when CI fails in Week 5 you know it is CI's fault and not your machine's:

$ python -m venv .venv
$ source .venv/bin/activate      # Windows: .venv\Scripts\activate
$ pip install -e ".[dev]"
$ pytest -q

Then open Claude Code in the repository — claude — and ask it to describe the project. It will read the CLAUDE.md and CONTEXT.md that ship with the template. Those files are why an agent can be useful here on its first turn instead of its tenth.

Self-check

1. You create a repository from a template and run git log. How much history do you expect?

C. GitHub's documentation is explicit: a repository created from a template "starts with a single commit," whereas a fork "includes the entire commit history of the parent repository." That is the central difference between the two, along with the contributions graph.

2. Why does this course insist your Instance be public?

B. Merge queue is available in any public repository owned by an organization, but for a private repository it requires GitHub Enterprise Cloud — so M29 would be unreachable on a private Instance. Public repositories also run Actions for free. (C is false — gh reads private repos fine; D is false — Actions runs on private repos, it just consumes metered minutes.)

3. Your organization membership is set to Private. What breaks later?

D. Anthropic's Code Review documentation notes that when organization membership is private, GitHub does not identify you as a member, so Claude will not act on your request even though a team gives you write access. The fix is to make membership public, or be added to the repository as a direct collaborator.

4. gh refuses a command and mentions a missing scope. What is the cheapest correct fix?

A. gh auth refresh -s adds scopes to the token you already have, without a full re-login. B works but is needless; C bypasses the credential store you already have; D confuses a token scope (what your token is permitted to ask for) with a repository permission (what your account is allowed to do) — they are different things, and only the first is yours to change.
