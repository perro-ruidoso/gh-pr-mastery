Decision B — The triage label vocabulary

When /triage processes an incoming issue, the skill explains, "it moves it through a state machine — needs evaluation, waiting on reporter, ready for an AFK agent to pick up, ready for a human, or won't fix." To do that it applies labels, and it needs those labels to match strings you have actually configured. This file maps each of five canonical roles to the label string your repository uses:

RoleMeaning
needs-triageMaintainer needs to evaluate this issue
needs-infoWaiting on the reporter for more information
ready-for-agentFully specified — an agent can pick it up with no human context
ready-for-humanRequires human implementation
wontfixWill not be actioned

Accept the defaults. The mapping exists so that a repo already using, say, bug:triage can point the skills at its own vocabulary instead of growing a duplicate set of labels — but your Instance starts clean, so the canonical strings are correct.

ready-for-agent is the one to watch

Of the five, that label carries the most weight in this course. It asserts something strong: this issue is specified well enough that a fresh session, with no memory of the conversation that produced it, can execute it. Week 2 is largely about earning the right to apply it, and the gap between an issue you understand and an issue that label describes is where most agentic work quietly fails.

Make the labels real

The mapping file names five strings. Nothing in the skill creates the labels themselves, so make them exist:

$ for L in needs-triage needs-info ready-for-agent ready-for-human wontfix; do
    gh label create "$L" --repo perro-ruidoso/flashcards-<your-handle> || true
  done

Two things to know about that loop. gh label create takes optional --color and --description, and "if a color isn't provided, a random one will be chosen"; --force updates an existing label instead of failing. And the || true is not paranoia: wontfix already exists. It is in GitHub's default label set, which every new repository receives whether or not it came from a template — the course confirmed this by deleting wontfix from the template and watching it reappear on a fresh Instance. Four of the five are yours to create; the fifth arrives free.

Decision C — Domain docs

Some skills — the skill names /improve-codebase-architecture, /diagnosing-bugs, and /tdd — read a CONTEXT.md for the project's domain language, and docs/adr/ for past architectural decisions. The skill asks whether this repo has one context or several.

Choose single-context. Your Instance is one small application; a CONTEXT.md already ships with the template, defining what a deck, a card, an interval, and an ease factor mean in this codebase, and a docs/adr/ with one decision already recorded. Multi-context — a CONTEXT-MAP.md pointing at several CONTEXT.md files — is for monorepos with genuinely separate frontend and backend vocabularies.

What you end up with

Before it writes anything, the skill shows you a draft and lets you edit. Then it produces:

  • docs/agents/issue-tracker.md — how to create, read, label, and close work
  • docs/agents/triage-labels.md — the five roles mapped to your label strings
  • docs/agents/domain.md — where CONTEXT.md and ADRs live, and the rules for reading them
  • An ## Agent skills section added to your existing CLAUDE.md, summarising all three and pointing at the files

Commit all of it. These files are part of the repository's contract with every future agent session, which makes them exactly as reviewable as code — and in Week 4 you will review a change to one.

One number space, two kinds of thing

Worth internalising before Week 2: GitHub shares a single number space between issues and pull requests, so a bare #42 may be either one. If you are scripting, resolve it explicitly — try gh pr view 42 and fall back to gh issue view 42. This trips up more automation than any other GitHub quirk.

Hands-on checklist

A1's checker verifies that the three files exist and are committed, that CLAUDE.md has the section, and that the four labels you create exist on the repository (wontfix is only noted — it arrives with every new repository — and fails only if you delete it).

Self-check

1. What is the strongest claim the ready-for-agent label makes?

D. That is the bar — "fully specified, AFK-ready." Size correlates but is not the claim, and it does not forbid a human from picking the work up. Week 2 exists largely to teach you how to write an issue that genuinely earns the label.

2. A script does gh issue view 42 and errors, though you can see #42 in the repository. Most likely cause?

A. GitHub numbers issues and pull requests from one sequence, so any bare reference is ambiguous. Resolve by trying gh pr view and falling back to gh issue view. (B is false — view reads closed issues fine. C and D are possible in general but would fail differently, and you said you can see it in this repo.)

3. gh label create wontfix fails with "already exists" on a brand-new Instance you have not touched. Why?

C. Verified by experiment when the template was built: wontfix was deleted from the template and still appeared on a freshly created Instance. Templates do not copy labels; GitHub's defaults arrive on every new repo. The skill writes a mapping file and never creates labels, and labels are per-repository, not per-org.

4. Which layout do you choose in Decision C for your Instance, and what signals the other one?

B. Layers inside one application share one vocabulary — a card means the same thing in the CLI as in storage. Multi-context is for repositories with genuinely separate bounded contexts (a monorepo's frontend and backend, say), marked by a root CONTEXT-MAP.md pointing at per-context CONTEXT.md files. The skill supports both; your Instance simply is not one of them.

Recite the five canonical triage roles, in state-machine order.
needs-triage → needs-info → ready-for-agent / ready-for-human → wontfix.
Meaning of needs-triage and needs-info?
needs-triage: a maintainer must evaluate it. needs-info: waiting on the reporter for more information.
Meaning of ready-for-agent — the strong version?
Fully specified, AFK-ready: a fresh session with no memory of the originating conversation can execute it with no further human context.
Meaning of ready-for-human and wontfix?
ready-for-human: requires human implementation. wontfix: will not be actioned.
Why does gh label create wontfix fail on a brand-new Instance?
wontfix is a GitHub default label on every new repository. Templates do not copy labels. Four of the five are yours to create; the fifth is free.
What does triage-labels.md actually do — create labels, or something else?
Something else: it maps the five roles to the label strings your repo uses. You create the labels yourself with gh label create.
Single-context vs multi-context: how does a skill tell them apart?
Single: CONTEXT.md + docs/adr/ at the root. Multi: a root CONTEXT-MAP.md pointing at per-context CONTEXT.md files (monorepos).
