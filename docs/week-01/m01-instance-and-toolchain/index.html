The three repositories, and which one is yours

This course uses three repositories, and confusing them is the single most common Week 1 mistake.

Course repo gh-pr-mastery

These pages. You read it; you never push to it. You will analyse its pull requests in M06.

Template flashcards-seed

A Python flashcard CLI with tests, CI, and a prepared backlog. You never push here either — you make a copy of it.

Yours flashcards-<handle>

Your Instance: your own copy of the template, created on the next page, worked in for six weeks.

A fourth, flashcards-upstream, appears in Week 5. Ignore it for now.

Step 1 — Accept the organization invitation

You will have an email invitation to the course organization, perro-ruidoso. Accept it, then make your membership public:

  1. Go to the organization's People tab.
  2. Find yourself, and change your membership visibility from Private to Public.
Why this one matters later

GitHub hides organization membership by default. When your membership is private, other tools — including the Claude GitHub App we use in Week 5 — cannot see that the organization grants you write access, and will refuse to act on your comments. Anthropic's documentation calls this out explicitly. Two minutes now saves a confusing hour in Week 5.

Step 2 — Authenticate gh with the right scopes

Install the GitHub CLI if you have not, then:

$ gh auth login
$ gh auth status

The status output tells you the account and — the part people skip — the token scopes:

github.com
  ✓ Logged in to github.com account your-handle (keyring)
  - Active account: true
  - Git operations protocol: https
  - Token: gho_************************************
  - Token scopes: 'gist', 'read:org', 'repo', 'workflow'

Those four scopes are enough for everything through Week 4. A scope is a permission attached to your token; if a command needs one you do not have, gh fails with a message naming it. You can add scopes at any time without logging in again:

$ gh auth refresh -s read:project

Two details from the gh auth refresh manual are worth knowing before you need them. The --scopes flag takes a comma-separated list and adds to what you have — "if no scopes are provided, the command maintains previously added scopes." And there is a floor: "the minimum set of scopes (repo, read:org, and gist) cannot be removed." If you ever over-grant, --remove-scopes takes scopes away and --reset-scopes returns you to the default set.

Check your own

Run gh auth status now and read the scopes line. If repo and read:org are missing, nothing else in this course will work. A1's checker reads this, so fix it today rather than on the due date.

Scope versus permission

A token scope is what your token is allowed to ask for. A repository permission is what your account is allowed to do. A missing scope is yours to fix with gh auth refresh; a missing permission is an org owner's to grant. When gh refuses you, read the error to see which of the two it is naming.

With membership public and scopes confirmed, you are ready to create your Instance.

Self-check

1. Which repository do you push your own work to during this course?

C. The Instance is the only one of the three that is yours. You read the course repo and analyse its history; you copy the template but never push to it. The upstream repo does become a push target — but not until Week 5, and even then as a shared repository with its own rules.

2. Your organization membership is set to Private. What breaks later?

D. Anthropic's documentation notes that when organization membership is private, GitHub does not identify you as a member, so Claude will not act on your request even though a team gives you write access. The fix is to make membership public, or be added to the repository as a direct collaborator.

3. gh refuses a command and mentions a missing scope. What is the cheapest correct fix?

A. gh auth refresh -s adds scopes to the token you already have, without a full re-login. B works but is needless; C bypasses the credential store you already have; D confuses a token scope (what your token is permitted to ask for) with a repository permission (what your account is allowed to do) — they are different things, and only the first is yours to change.

4. You run gh auth refresh --remove-scopes repo. What happens?

B. The manual is explicit: "the minimum set of scopes (repo, read:org, and gist) cannot be removed." D describes --reset-scopes, a different flag. This matters because the two scopes A1 depends on are exactly the ones you cannot lose by accident.
