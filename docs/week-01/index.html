GitHub Pull Requests for Agentic Coders Week 1

Week 1 — The Machine You Work In

Before you can run work through pull requests, you need an accurate model of what a pull request is — and a repository, a terminal, and an agent configured to work in it.

Most people who have used GitHub for a year still hold a fuzzy model of the pull request: something like "a request to merge my branch." That model is close enough to open a PR and wrong enough to produce the three most common confusions in this course — why does my PR show a file I never touched?, why did my PR change when someone else merged?, and what exactly am I comparing against? This week replaces the fuzzy model with a precise one, then gets your tooling into a state where the rest of the course can be hands-on.

Suggested order

Do M01 first — it gives you a real repository to point the next two pages at. M02 and M03 are the conceptual core of the whole course; take them slowly. M04 and M05 are tooling. M06 asks you to turn the week's model on a real artifact and write up what you see.

Learning pages

  • M01Apply
    Your Instance and Your Toolchain

    Join the org, refresh your gh scopes, and create your own copy of the flashcard CLI from the course template — and see why it is a template, not a fork.

  • M02Understand
    What a Pull Request Actually Is

    Two refs and a conversation. Base and head, why head can live in someone else's repository, and what draft state really changes.

  • M03Understand
    The Merge Base, and Why Your Diff Looks Like That

    Three dots versus two. The single idea that explains most "why is that file in my PR?" confusion — and why your diff stays stable when main moves.

  • M04Apply
    Reading Work From the Terminal

    gh issue list, gh pr view --json, gh pr diff. Structured output you can pipe, script, and hand to an agent.

  • M05Apply
    Teaching Your Repo to the Skills

    Three decisions — issue tracker, triage labels, domain docs — that every engineering skill you use for the next five weeks will read.

  • M06Analyze
    Reading the Exhibit

    This course's own repository was built with the workflow it teaches. Read its issues and PRs and reconstruct the process from the evidence.

Assignment A1

Due before the Week 2 meeting. The full brief is in assignments/a1.md; in short:

  1. Instance created from the template, named flashcards-<your-github-handle>, public, in the course org.
  2. gh authenticated with the required scopes; a gh pr view --json command run against a real PR and its output pasted into your write-up.
  3. /setup-matt-pocock-skills run and its three output files committed.
  4. A short written analysis (roughly 300 words) of one pull request in the course repository: what it changed, what it was blocked by, and how you can tell.

Most of A1 is graded by a script that reads your repository's actual state — see the checker in checkers/check_a1.py. The written analysis is graded by a human against a rubric. Nothing is graded on whether you typed the code yourself.

Assigned sources

  • GitHub Docs: About pull requests
  • GitHub Docs: About comparing branches in pull requests — the important one
  • GitHub Docs: Creating a repository from a template
  • GitHub CLI manual — skim gh pr and gh issue
