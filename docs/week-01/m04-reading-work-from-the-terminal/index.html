Listing and Viewing

The web UI is for humans reading one thing. The CLI is for asking precise questions, getting structured answers, and handing them to an agent.

M04 · Tooling Bloom: Apply Assessed by: A1 (checker)

Objective: Inspect issues and PRs from the terminal with gh issue/pr list, view, and diff, including --json field selection.

M04 pages 1Listing and Viewing 2Filter and Diff

Why not just use the website?

Use the website — it is excellent. But three things only the CLI gives you, and all three matter in this course:

  • Precision. "Which open PRs target a base other than main?" is one command, not twenty clicks.
  • Structure. --json returns data you can filter, count, and assert on. Every assignment checker in this course is built from it.
  • Agent parity. When Claude works with GitHub, it uses these same commands. Knowing what they return means you can read what your agent did, and tell it exactly what to run.
Try these against a real repository

Every command on this page uses -R cli/cli — the GitHub CLI's own public repository — so you can run them right now, before your Instance has any interesting history. -R (long form --repo) points a command at a repository other than the one in your current directory. Your numbers will differ from the outputs shown; the shapes will not.

Listing: what is in flight?

$ gh pr list -R cli/cli --limit 3 
14398  Check for merged state when viewing a PR via the issues command  timmattison:issue-12195   OPEN   2026-09-08T18:25:17Z
14373  docs: Add step to install working version on Ubuntu Pro          acoulton:patch-1          OPEN   2026-09-07T10:43:26Z
14355  Remove obsolete Git test seams                                   williammartin-clean-git-test-seams  DRAFT  2026-09-04T15:50:28Z

Number, title, head ref, state, age. Note the third column again — owner:branch means a fork, as M02 covered.

Two defaults from the manual are worth knowing, because they silently shape what you see: --limit defaults to 30 items, and --state defaults to open (the choices are open, closed, merged, all). A "how many PRs does this repo have?" question answered with the defaults is actually "how many of the first thirty open ones" — raise the limit and widen the state before you count anything.

Viewing: the fields that matter

Plain gh pr view 14398 -R cli/cli prints a readable summary. Add --json and you choose exactly what you get:

$ gh pr view 14398 -R cli/cli --json number,title,state,isDraft,baseRefName,headRefName,additions,deletions,changedFiles 
{
  "additions": 2,
  "baseRefName": "trunk",
  "changedFiles": 1,
  "deletions": 0,
  "headRefName": "issue-12195",
  "isDraft": false,
  "number": 14398,
  "state": "OPEN",
  "title": "Check for merged state when viewing a PR via the issues command"
}

Two lines added, one file touched. That is a reviewable diff — a judgement you will make formally in Week 3.

Discovering the field names

You do not need to memorise them. Ask for a field that does not exist and gh lists the real ones:

$ gh pr view 14398 -R cli/cli --json nope 
Unknown JSON field: "nope"
Available fields:
  additions
  assignees
  author
  autoMergeRequest
  baseRefName
  baseRefOid
  …and about forty more, including closingIssuesReferences,
  isCrossRepository, reviewDecision, and statusCheckRollup
A trick worth keeping

Deliberately asking for a bogus field is the fastest way to see what a gh command can return. It works for gh issue view, gh pr list, gh repo view, and gh run list too — any command that accepts --json.

The same --json flag works on list commands, where it returns an array of objects instead of one object. That is what the next page filters with --jq.

Hands-on checklist

A1's checker looks for evidence of item 2 in your write-up.

Self-check

1. You cannot remember what fields gh pr view --json accepts. Fastest way to find out, without leaving the terminal?

B. gh pr view N --json nope prints Unknown JSON field: "nope" followed by every valid field. (A prints a human summary but not the field names; C works but is enormous overkill; D is simply false.)

2. What does -R cli/cli do in gh pr list -R cli/cli?

C. -R / --repo selects the repository, in OWNER/REPO form. Without it, gh infers the repository from the git remote of your current directory — which is why every example here names one explicitly, so it works from any folder.

3. gh pr list -R OWNER/REPO with no other flags prints 30 rows. What have you actually counted?

A. The manual gives --limit a default of 30 and --state a default of open. Exactly 30 rows is the signature of a truncated list, not a coincidence. Pass --state all --limit 200 (or larger) before you count, and check whether you hit the limit again.

4. Why does this course care that you and your agent read GitHub through the same gh commands?

D. Agent parity. When the surface is shared, the agent's actions are legible to you and your instructions are unambiguous to it. Week 4 depends on this: reviewing what an agent did to a PR means reading the same fields it wrote.

Flashcards

Say the answer out loud before you flip. "Again" puts the card back in the queue; "Got it" retires it. Keyboard: Space flips, 1 again, 2 got it.

What does -R OWNER/REPO do on a gh command?
Targets that repository instead of the one inferred from your current directory's git remote. Long form: --repo.
Default --limit and default --state for gh pr list?
30 items, open state. Exactly 30 rows means you hit the limit. States: open, closed, merged, all.
Name the five columns of default gh pr list output.
Number, title, head ref (as owner:branch for forks), state, and timestamp.
What does --json a,b,c change about a gh command's output?
It emits JSON containing only the named fields — one object for view, an array of objects for list.
Fastest way to discover the valid --json field names?
Ask for a bogus one: gh pr view N --json nope prints "Unknown JSON field" and the full list of available fields.
Which five fields does A1 want in your pasted gh pr view --json output, at minimum?
Any five, but two are mandatory: baseRefName and headRefName. Good extras: number, state, isDraft, changedFiles.
The three things the CLI gives you that the website does not?
Precision (one command, not twenty clicks), structure (--json you can filter and assert on), and agent parity (the same surface your agent uses).
Ask your teacher

Stuck on a command? Paste the exact error into Claude Code and ask it to explain the error before it proposes a fix — then run the fix yourself and read the output. If you want a drill, ask it to "give me five gh pr view --json questions about cli/cli and check my commands." Bring anything still unclear to the weekly meeting.
