What a skill is, and who gets to start one

Anthropic's documentation: "Skills extend what Claude can do. Create a SKILL.md file with instructions, and Claude adds it to its toolkit. Claude uses skills when relevant, or you can invoke one directly with /skill-name." Every skill has "YAML frontmatter between --- markers that tells Claude when to use the skill, and markdown content with the instructions Claude follows when the skill runs. The directory name becomes the command you type, and the description helps Claude decide when to load the skill automatically."

One front-matter field decides who can start a skill. From the same page: "To keep a personal or project skill but stop Claude from invoking it on its own, set disable-model-invocation: true in its frontmatter, or “user-invocable-only” in skillOverrides when you don’t want to edit the file." The skills repository's README draws the same line in its own words: "User-invoked skills are reachable only when you type them (e.g. /grill-me); their job is to orchestrate. Model-invoked skills can be invoked by you or reached for automatically by the agent when the task fits; they hold the reusable discipline. A user-invoked skill may invoke model-invoked skills, but never another user-invoked one." That is why /resolving-merge-conflicts could have started on its own when M17's merge stopped, and /ask-matt never will.

Two sentences in the file matter beyond routing. On context: "Keep steps 1–3 in one unbroken context window — don't compact or clear until after /to-tickets — so the grilling, spec, and tickets all build on the same thinking. Each /implement then starts fresh, working from the ticket." That is the Week 2 sequence you ran, with the reason. And on the limit: "the smart zone: the window (~120k tokens on state-of-the-art models) within which the model still reasons sharply. If a session approaches it before /to-tickets, don't push on degraded — /handoff and continue in a fresh thread." That is the 2026-07-09 copy. The upstream router was rewritten on 2026-08-05: the figure is now "~150k tokens", the advice is "/compact at the nearest phase boundary and carry on", and a new Phase boundaries section ranks five options — continue, /clear, /handoff ("Narrow: only for a new harness, a new directory, a colleague, or forking a side task mid-phase"), a subagent, and /compact ("The default"). A plugin install carries the new text; page 2's handoff entry is written so that it holds under both.

What the installed copy does not match upstream

The installed skills are a snapshot dated 2026-07-09. The upstream repository, read 2026-09-13 and again 2026-09-14 (head 3cca18b, 2026-09-04), has moved further than the first reading found. The differences that touch this objective:

  • request-refactor-plan no longer exists upstream. The commit c66bdee, 2026-08-05, "chore: remove six unused skills and the personal bucket," deleted it; the repository's deprecated/README.md says "a retired skill is deleted, and the changeset that removes it names whatever replaced it." The changeset that removed it names the replacement: "request-refactor-plan → /to-spec and /improve-codebase-architecture" — and, in the same list, "qa → /triage and /to-tickets". Both are still installed on the course machine and still run; page 2 quotes request-refactor-plan from the installed file and says so.
  • Descriptions and bodies were reworded, not only re-punctuated. A commit on 2026-08-19 removed every em-dash from the repository, so wayfinder's upstream description reads "(more than one agent session can hold)" where the installed one reads "— more than one agent session can hold —". But it also says "decision tickets" where the installed file says "investigation tickets" (renamed 2026-07-13, four days after the snapshot); grilling's description and body were rewritten between 2026-07-13 and 2026-08-20 into a round-by-round format; grill-me's one-line body became "Call the Skill tool with “grilling”." on 2026-08-15; and to-tickets, to-spec, and code-review each changed a few words. Page 2 quotes the installed text and marks each divergence, because on the course machine that is what runs — on a plugin install it is not.
  • git-guardrails-claude-code lives in skills/misc/, whose README calls its contents "Tools I keep around but rarely use, not promoted in the plugin." It is not in ask-matt's map either. Installed on the course machine, working, off the route.
What the plugin gives you (checked 2026-09-14)

The setup handout installs the skills as the Claude Code plugin, and the plugin's manifest (.claude-plugin/plugin.json, version 1.2.3) lists twenty-five skills: the engineering and productivity buckets, updated whenever upstream ships. It does not contain request-refactor-plan or qa (deleted upstream), git-guardrails-claude-code (kept in misc, "not promoted in the plugin"), or claude-handoff (in-progress). So two of the six skills this objective names are ones a plugin install cannot run: you can read their descriptions here, and you can add git-guardrails-claude-code by itself with the other installer (npx skills@latest add mattpocock/skills, which lets you pick skills), but request-refactor-plan exists only as the course machine's 2026-07-09 copy. The course machine's ~/.agents/skills/ is that older, fuller snapshot (38 skills); the pages say which copy each quotation is from.

The lesson is the one M05 gave for CLAUDE.md: read the installed file, not the README, when you want to know what will happen.

Self-check

1. /ask-matt has disable-model-invocation: true; /resolving-merge-conflicts does not. What follows?

B. The flag "stop[s] Claude from invoking it on its own"; both can be typed (A). Calling other skills is about user- versus model-invoked orchestration, not tool use (C). D confuses the flag's subagent effect with its main purpose.

2. According to the router, where do to-spec and to-tickets sit, and what must be true of the context around them?

D. "Keep steps 1–3 in one unbroken context window — don't compact or clear until after /to-tickets." Fresh sessions are for each /implement, not for the spec (A). B and C place them in the wrong sections.

3. Why does this course quote the installed SKILL.md files rather than the repository README?

A. request-refactor-plan and qa were deleted upstream on 2026-08-05 and are still installed here; the smart-zone figure and the handoff/compact advice changed the same day; the installed copies are older, not newer (B). The README does show descriptions (C) and lists both kinds (D).
