GitHub Pull Requests for Agentic Coders Week 3

Week 3 — Branches and the Shape of a Diff

A ticket becomes a branch, a branch becomes a pull request, and the pull request closes the ticket. This week you run that loop twice, stack the second run on the first, retarget it when the first lands, and resolve the conflict a third ticket causes on the way.

Week 2 gave your Instance a backlog with real blocking edges. Nothing has been built against it yet. This week two of those tickets — a pair that share an edge — go through gh issue develop, a diff you have read as a reviewer, a PR body that says what it did and how you know, and a merge that closes the issue without anyone touching it. The second ticket is stacked on the first, which is where the week's two hard facts live: a closing keyword is ignored until the PR targets main, and a squash-merged parent makes the child's diff grow until you rebase. A third ticket then collides with the second, and you resolve the conflict with /resolving-merge-conflicts, reading what it does at each step.

Suggested order

The objectives are the order of the work. M13 creates the branch; M14 is the reviewer's eye you apply to your own diff before anyone else sees it; M15 is the PR body and the keyword; M16 is the stack and the retarget, the idea of the week; M17 is the conflict. M18 is the rest of the skill toolbelt and can be read any time — do its flashcards twice, a few days apart. Every transcript on these pages was run on a throwaway Instance on 2026-09-13; the numbers on your Instance will differ, the shapes will not.

Two things that surprised the course itself

A stacked PR's Closes #n does nothing until the base is the default branch — the course repo's own PR #14 sat with an empty closingIssuesReferences for 33 minutes with the keyword in its body, and populated only after it was retargeted (on the throwaway, the link event landed one second after the retarget). And gh pr merge --delete-branch on a parent closes the child PR outright; only GitHub's own Automatically delete head branches setting retargets it. Both are on the M16 pages with the timestamps.

Assignment A3

Due before the Week 4 meeting. The full brief is in assignments/a3.md; in short:

  1. Two tickets from your backlog that share a blocking edge; A's branch created with gh issue develop.
  2. A shipped as a reviewable PR with a four-section body and Closes #A; the diff read as a reviewer first.
  3. A merged; the issue closed itself within seconds.
  4. B stacked on A's branch, retargeted to main after A merged, rebased after the squash.
  5. A third ticket merged in between, the conflict on B resolved with /resolving-merge-conflicts, B merged.
  6. A short write-up: what caused the conflict, what the drive-by was, and three situations matched to three skills.

Items 1–5 leave evidence checkers/check_a3.py reads: branch names, PR headings, closing links, the base-change event, the two-parent merge commit, the close timestamps. Reviewability, the honesty of the bodies, and item 6 are graded by a human against the rubric.

  • GitHub CLI manual: gh issue develop, gh pr create, gh pr edit
