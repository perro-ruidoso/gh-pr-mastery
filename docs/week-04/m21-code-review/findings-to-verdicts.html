From Findings to Verdicts

A finding is a candidate, not a defect. The vocabulary

CONTEXT.md for this course: a Finding is "One item reported by an automated review … before a human has judged it. A finding is a candidate, not a defect." A Verdict is "A human's disposition of a finding: must-fix, nit, or false positive." Must-fix: the PR should not merge with it. Nit: real, worth fixing, not blocking. False positive: the finding is wrong, or is about something other than what it claims. A fourth disposition, duplicate, is not a verdict — it is a finding that restates another and inherits its verdict.

What the tally says

Four must-fix (three planted, plus the test rewrite that hid them), four nits (one mislabelled), one false positive, one duplicate, and two non-findings — out of the "6 hard + 3 smells" and "3 + 1 + 1" the axes reported. The agents missed nothing that was planted and invented nothing that was not there; the noise was a wrong number, a claim about a document the agent had not opened, a smell with the wrong name, and one defect stated twice. None of it would have survived a reviewer who read the PR body and ran two commands — and all of it would have been repeated verbatim by a reviewer who did not.

The decoys were the agents', not the planter's

seed/SPEC.md §7 asks each planted bug to have "a decoy: at least one /code-review finding that is a genuine nit or a false positive". The planted diff put a few in reach — the stale docstring, the ef rename, the nested conditional — and the agents took them, but the false positive that mattered (finding 6) was one nobody planted: an agent reasoning from the commit message about a rule that binds the PR description. You cannot anticipate every false positive; you can make it a habit to ask, for each finding, "what did it read, and did I read it too?"

Writing it up

Assignment A4's written part is this page, for your peer's PR: the two reports pasted unedited under ## Standards and ## Spec, then a table like the one above with a verdict per finding and, for every must-fix, the ADR or ticket sentence it violates. check_a4.py reads only the evidence — that the two headings are there, that the three verdict words appear, that it is long enough to have said something. Whether the verdicts are right is the rubric's job, and the rubric's first question is whether you verified what could be verified.

Self-check

1. The Standards agent wrote: "The commit message names none [of the ADR rules]; if the PR body matches, that's a breach." Why is this a false positive rather than a nit?

C. The rule: "A pull request that changes scheduling arithmetic must say, in its description, which rule…". The body says Ease Factor, Failure, Rounding. The agent read the commit, and its "if" was an admission. A invents a condition; B is wrong (step 1 also notes the commit list); D confuses the baseline with documented standards.

2. Which §5 rule does planted bug 1 — the floor applied before the update — violate?

B. The floor belongs to the updated value. The clamp does not touch a new card's 2.5 (A) or the failure path (C, which is bug 2's rule); the interval rule (D) is downstream of whichever EF you compute — the defect is in the EF, not the multiplication.

3. The Standards agent labelled the nested conditional expression "Primitive Obsession (magic literals)". What is the right disposition?

D. Keep the substance, fix the name. Smells are judgement calls but still findings (A); nothing documented is breached (B); the complaint is about the if/else chain, not the rounding (C).

4. What is the first thing this page did before assigning any verdict?

A. "Verify first" — and one number changed (5 → 4). The Pocock skill has no effort levels (B); the author's agreement is not evidence (C); ranking across axes is what the skill forbids (D).

Ask your teacher

Paste your two reports into Claude Code and ask: "for each finding, name the document and sentence it rests on, and tell me whether you actually opened that document during the review." Then open them yourself. Where the answer is "I inferred it", you have a candidate false positive; where you and the agent read the same sentence differently, bring both readings to the weekly meeting.
